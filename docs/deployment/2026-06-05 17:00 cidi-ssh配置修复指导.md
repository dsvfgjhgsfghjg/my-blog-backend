# CI/CD SSH 配置修复指导（给后端/运维）

## 问题现象

CI/CD 部署阶段（deploy job）执行 SSH 命令时失败：

```
kex_exchange_identification: read: Connection reset by peer
Connection reset by *** port 22
Error: Process completed with exit code 255.
```

## 根因（已定位确认）

**云端 sshd 被全网 SSH 暴力破解打爆了**：

```
# 默认 sshd 配置（未经任何加固）
maxstartups 10:30:100      # 未认证连接 >10 就开始丢，>100 全丢
passwordauthentication yes  # 接受密码登录（被海量暴力破解利用）
logingracetime 120          # 失败连接在 sshd 进程里挂 2 分钟
maxauthtries 6

# auth.log 统计
4155+ 次 MaxStartups throttling 丢弃事件
5 分钟内 TOP 攻击 IP：
  598 from 1.71.254.53
  383 from 36.111.171.140
  160 from 42.123.122.110
```

### 关键证据

1. Runner 容器（172.18.0.4）单连接 SSH 能成功，并发 6 个就有 2 个被 RST
2. 云端 auth.log 持续出现 `error: beginning MaxStartups throttling / drop connection ... past MaxStartups`
3. 加固后 CI 零报错，部署成功

## 修复命令（逐条执行，不依赖脚本）

### 1. 确认当前 sshd 配置

```bash
ssh ubuntu@113.31.105.30
sudo sshd -T 2>/dev/null | grep -iE "maxstartups|passwordauth|pubkeyauth|usepam|authmethods"
```

确认看到：`maxstartups 10:30:100`、`passwordauthentication yes`

### 2. 备份

```bash
sudo cp -a /etc/ssh/sshd_config /etc/ssh/sshd_config.bak.$(date +%Y%m%d)
sudo cp -a /etc/ssh/sshd_config.d/50-cloud-init.conf /etc/ssh/sshd_config.d/50-cloud-init.conf.bak
```

### 3. 覆盖 cloud-init 生成的 50-cloud-init.conf（它在sshd_config Include之前加载）

**要点**：50-cloud-init.conf 默认内容是 `PasswordAuthentication yes`，优先级高于我方后续加的 .conf 文件，必须直接覆盖它。

```bash
echo 'PasswordAuthentication no' | sudo tee /etc/ssh/sshd_config.d/50-cloud-init.conf
sudo chmod 600 /etc/ssh/sshd_config.d/50-cloud-init.conf
```

### 4. 写入加固配置

```bash
sudo tee /etc/ssh/sshd_config.d/99-myblog-hardening.conf > /dev/null <<'EOF'
# MyBlog CI/CD SSH 加固（2026-06-05）
PubkeyAuthentication yes
PasswordAuthentication no
PermitEmptyPasswords no
ChallengeResponseAuthentication no
AuthenticationMethods publickey
UsePAM yes
MaxStartups 50:100:200
LoginGraceTime 30s
MaxAuthTries 3
ClientAliveInterval 30
ClientAliveCountMax 6
PermitRootLogin prohibit-password
EOF
```

### 5. 在主 sshd_config 的 Include 之前也写加固行（双保险，cloud-init 改不到）

```bash
INCLUDE_LINE=$(grep -n "^Include /etc/ssh/sshd_config.d/" /etc/ssh/sshd_config | cut -d: -f1)
sudo sed -i "${INCLUDE_LINE}iPasswordAuthentication no\nChallengeResponseAuthentication no\nAuthenticationMethods publickey" /etc/ssh/sshd_config
```

### 6. 校验并 reload

```bash
sudo sshd -t && echo "✓ 配置OK" && sudo systemctl reload ssh
```

### 7. 屏蔽当前暴力破解 IP（iptables）

```bash
for ip in 1.71.254.53 36.111.171.140 42.123.122.110 87.251.64.147 \
          39.164.126.118 197.225.146.23 180.76.227.187 2.57.121.25; do
  sudo iptables -C INPUT -s "$ip" -p tcp --dport 22 -j DROP 2>/dev/null || \
  sudo iptables -I INPUT -s "$ip" -p tcp --dport 22 -j DROP
done
```

### 8. 持久化 iptables

```bash
sudo apt-get install -y iptables-persistent
sudo netfilter-persistent save
```

### 9. 验证加固生效

```bash
sudo sshd -T 2>/dev/null | grep -iE "passwordauth|authmethods|maxstartups"
# 期望看到：
#   authenticationmethods publickey
#   maxstartups 50:100:200
#   passwordauthentication no
```

### 10. 验证 SSH 直登 + sudo

```bash
ssh -i ~/.ssh/id_ed25519 ubuntu@113.31.105.30 'echo OK'
# 期望：OK

ssh -i ~/.ssh/id_ed25519 -t ubuntu@113.31.105.30 'sudo whoami'
# 期望：提示输入 ubuntu 本地密码
```

## 一点背景

### sshd 配置加载顺序

```
/etc/ssh/sshd_config
  ├── [主文件，Include 之前的内容，优先级最高]
  ├── Include /etc/ssh/sshd_config.d/*.conf  [按字母序加载]
  │   ├── 50-cloud-init.conf  ← 如果是 PasswordAuthentication yes 会覆盖！
  │   └── 99-myblog-hardening.conf
  └── [主文件，Include 之后的内容]
```

**陷阱**：50-cloud-init.conf 的内容如果与主文件冲突，**主文件 Include 前的行优先**，但 50-cloud-init.conf 本身（如果在 sshd_config.d 目录里是唯一设置方）也能覆盖默认值。

我们的做法：
- 在 Include 之前插入 `PasswordAuthentication no` ← 主文件优先
- 覆盖 50-cloud-init.conf 的 `PasswordAuthentication yes` → `no` ← 双保险

### Runner 侧

- Runner 容器（172.18.0.4）已挂载 `/var/run/docker.sock`，SSH 密钥 `deploy_key` 已正确配置
- 不需要改动 Runner 配置
- 如果未来需要更鲁棒，CI workflow 可加 `ssh -o ServerAliveInterval=15` 和 scp 重试

## 回退方案

如果加固导致问题：

```bash
# 回退 sshd
sudo rm /etc/ssh/sshd_config.d/99-myblog-hardening.conf
sudo cp /etc/ssh/sshd_config.bak.20260605 /etc/ssh/sshd_config
sudo cp /etc/ssh/sshd_config.d/50-cloud-init.conf.bak /etc/ssh/sshd_config.d/50-cloud-init.conf
sudo systemctl reload ssh

# 清除 iptables DROP 规则
sudo iptables -F INPUT
sudo netfilter-persistent save
```
