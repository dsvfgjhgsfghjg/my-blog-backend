### ✅ V2 - IDOR用户信息枚举（已修复）

**问题**: `GET /api/users/{userId}` 接口允许任意用户查询其他用户信息

**修复位置**: `UserController.java`

**修复方案**:
```java
@GetMapping("/{userId}")
public Result<UserBasicResponse> getUserById(@RequestAttribute Long userId,
                                             @PathVariable Long targetUserId) {
    // 从数据库获取当前用户信息，判断是否为管理员
    com.leo.myblog.entity.User currentUser = userService.getUserById(userId);
    boolean isAdmin = currentUser != null && Boolean.TRUE.equals(currentUser.getIsAdmin());
    
    // 权限校验：只能查看自己的信息，或者管理员可以查看所有
    if (!userId.equals(targetUserId) && !isAdmin) {
        log.warn("无权查看他人信息: currentUserId={}, targetUserId={}", userId, targetUserId);
        return Result.error(403, "无权查看他人信息");
    }
    
    return Result.success(userService.getUserBasicInfo(targetUserId));
}
```

**验证方法**:
```bash
# 使用普通用户Token尝试查询其他用户信息，应返回403
curl http://113.31.105.30:8081/api/users/1 \
  -H "Authorization: Bearer <普通用户token>"
# 预期响应: {"code":403,"message":"无权查看他人信息","data":null}
```

### ✅ V3 - 登录频率限制（已修复）

**问题**: `POST /api/users/login` 接口无频率限制，可暴力破解密码

**修复位置**: 
- 新增 `LoginRateLimitService.java`
- 修改 `UserService.java`

**修复方案**: 实现渐进式账户锁定策略

1. **创建速率限制服务** (`LoginRateLimitService.java`):
   - 使用Redis记录登录失败次数
   - **渐进式锁定策略**:
     - 第1-5次失败：锁定3分钟
     - 第6-8次失败：锁定10分钟
     - 第9次及以上：每次锁定30分钟
   - 登录成功后清除失败计数

2. **集成到登录流程** (`UserService.login()`):
```java
// 检查是否被锁定
if (!loginRateLimitService.isLoginAllowed(normalizedUsername, clientIp)) {
    long remainingTime = loginRateLimitService.getRemainingLockTime(normalizedUsername, clientIp);
    long failureCount = loginRateLimitService.getFailureCount(normalizedUsername, clientIp);
    
    String lockMessage;
    if (failureCount <= 5) {
        lockMessage = String.format("密码错误次数过多，账户已锁定%d秒（第%d次失败）", remainingTime, failureCount);
    } else if (failureCount <= 8) {
        lockMessage = String.format("密码错误次数过多，账户已锁定%d秒（第%d次失败，锁定时间延长）", remainingTime, failureCount);
    } else {
        lockMessage = String.format("密码错误次数过多，账户已锁定%d秒（第%d次失败，严重警告）", remainingTime, failureCount);
    }
    
    throw new BusinessException(lockMessage);
}

// 登录失败时记录
loginRateLimitService.recordLoginFailure(normalizedUsername, clientIp);

// 登录成功时清除
loginRateLimitService.recordLoginSuccess(normalizedUsername, clientIp);
```

**配置参数**:
- 第一阶段: 1-5次失败 → 锁定3分钟
- 第二阶段: 6-8次失败 → 锁定10分钟
- 第三阶段: 9次及以上 → 锁定30分钟
- Redis Key格式: `login:failures:{username}:{ip}` 和 `login:lock:{username}:{ip}`
- 失败计数过期时间: 1小时

**验证方法**:
```bash
# 连续5次使用错误密码登录
for i in {1..6}; do
  curl -X POST http://113.31.105.30:8081/api/users/login \
    -H "Content-Type: application/json" \
    -d '{"username":"admin","password":"wrong_password"}'
done
# 第6次应返回: {"code":500,"message":"密码错误次数过多，账户已锁定180秒（第5次失败）","data":null}

# 等待3分钟后，继续尝试3次
# 第9次应返回: {"code":500,"message":"密码错误次数过多，账户已锁定600秒（第8次失败，锁定时间延长）","data":null}

# 第10次及以后应返回: {"code":500,"message":"密码错误次数过多，账户已锁定1800秒（第9次失败，严重警告）","data":null}
```

### ✅ V4/V11 - 文件上传漏洞（已修复）

**问题**: 头像上传接口仅校验扩展名，不验证文件内容，可能上传WebShell

**修复位置**: 
- `UserController.java` (用户头像)
- `BloggerInfoController.java` (博主头像)

**修复方案**: 添加 `Content-Disposition: attachment` 响应头，防止浏览器内联执行恶意脚本

```java
// 用户头像接口
headers.setContentDisposition(
    org.springframework.http.ContentDisposition
        .attachment()
        .filename("avatar" + getFileExtensionFromPath(avatarPath))
        .build()
);

// 博主头像接口
headers.setContentDisposition(
    org.springframework.http.ContentDisposition
        .attachment()
        .filename("blogger-avatar.jpg")
        .build()
);
```

**效果**:
- 浏览器会将文件作为附件下载，而不是直接在页面中渲染
- 即使上传了JSP/PHP WebShell，也无法通过浏览器直接执行
- 配合现有的MinIO存储和UUID文件名，安全性大幅提升

**现有安全措施** (已实现):
- ✅ 文件扩展名白名单校验 (.jpg, .jpeg, .png, .gif, .webp, **.svg**)
- ✅ MIME类型校验
- ✅ 文件魔数签名验证 (JPEG/PNG/GIF/WebP)
- ✅ UUID文件名防止猜测
- ✅ 文件大小限制 (5MB)
- ✅ Content-Disposition: attachment 响应头

**新增SVG安全防护**:
- ✅ **第1层**: XML解析器禁用外部实体（XXE防护）
- ✅ **第2层**: 移除高危元素（script、foreignObject、iframe等）
- ✅ **第3层**: 删除危险属性（on*事件处理器、javascript: href等）

```bash
  -H "Authorization: Bearer <token>"
```

### ✅ V12 - 博主信息未授权访问（已修复）

**问题**: `GET /api/blogger/info` 泄露博主真实邮箱

**修复位置**: `BloggerInfoService.java`

**修复方案**: 对邮箱进行脱敏处理

```java
private String maskEmail(String email) {
    if (email == null || email.isEmpty()) {
        return email;
    }
    
    int atIndex = email.indexOf('@');
    if (atIndex <= 1) {
        return email;
    }
    
    String localPart = email.substring(0, atIndex);
    String domainPart = email.substring(atIndex);
    
    if (localPart.length() <= 2) {
        return localPart.charAt(0) + "*" + localPart.charAt(localPart.length() - 1) + domainPart;
    } else {
        return localPart.charAt(0) + "*****" + localPart.charAt(localPart.length() - 1) + domainPart;
    }
}
```

**修复前**:
```json
{
  "email": "travelingbug@163.com"
}
```

**修复后**:
```json
{
  "email": "t*****g@163.com"
}
```

### ✅ V1 - 存储型XSS（已修复）

**问题**: 文章正文使用 `innerHTML` 渲染Markdown，可注入XSS窃取JWT

**修复方案**: 实施三层纵深防御体系

#### 第1层：后端 Jsoup 白名单清洗（`PostServiceImpl.java`）

**新增方法**:

1. **`cleanMarkdownContent(String markdownContent)`** - 主清洗方法
   - 使用 `Jsoup.clean()` + `POST_CONTENT_SAFELIST` 白名单过滤
   - **关键修复**: `Document.OutputSettings.prettyPrint(false)` 保留换行符，防止 Markdown 格式破坏
   - 只允许安全的标签（`p`, `h1-h6`, `strong`, `a`, `img`, `pre`, `code` 等）和属性

2. **`cleanMarkdownUrls(String markdownContent)`** - Markdown 链接协议清洗
   - 使用正则匹配 `[text](url)` 语法
   - 移除 `javascript:`、`vbscript:`、`data:`、`file:` 等危险协议链接
   - 将危险链接降级为纯文本（保留链接文字）

3. **`cleanRenderedHtmlContent(String htmlContent)`** - 备用 HTML 清洗方法
   - 同样使用 `prettyPrint(false)` 保留结构

**旧方法降级**: `checkMarkdownSafety()` 和 `sanitizeHtmlContent()` 标记为 `@Deprecated`，内部委托给新方法

#### 第2层：传输层安全（已配置）
- ✅ **HttpOnly Cookie**: JWT 已从 localStorage 迁移到 HttpOnly Cookie（`AUTH_TOKEN`）
- ✅ **CSP 响应头**: `script-src 'self' 'unsafe-inline'` 限制脚本来源
- ✅ **HSTS**: 1年强制 HTTPS

#### 第3层：前端 DOMPurify 二次清洗（需前端配合）

建议在 `PostDetail.vue` 中添加：

```javascript
import DOMPurify from 'dompurify'
import { marked } from 'marked'

const renderSafeMarkdown = (content) => {
  // 1. Markdown → HTML
  const html = marked.parse(content)
  // 2. DOMPurify 清洗（最终防线）
  return DOMPurify.sanitize(html, {
    ALLOWED_TAGS: ['p', 'h1', 'h2', 'h3', 'h4', 'h5', 'h6', 'ul', 'ol', 'li',
                   'blockquote', 'code', 'pre', 'img', 'a', 'strong', 'em',
                   'br', 'hr', 'table', 'thead', 'tbody', 'tr', 'th', 'td',
                   'dl', 'dt', 'dd', 'u', 's'],
    ALLOWED_ATTR: ['href', 'src', 'alt', 'title', 'target', 'class', 'width', 'height']
  })
}
```

